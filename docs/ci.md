# CI Quality Pipeline

Workflow: [`.github/workflows/test.yml`](../.github/workflows/test.yml) (GitHub Actions).
Generated by the BMad TEA `ci` workflow — see `_bmad-output/test-artifacts/ci-pipeline-progress.md` for full decisions.

## Stages

| Job | What | When |
|---|---|---|
| `lint-backend` | `uv run ruff check .` | every push/PR to `master` |
| `lint-frontend` | `npx tsc -b` (typecheck) | every push/PR to `master` |
| `test-backend` | `uv run pytest` + JUnit XML artifact | after lint-backend |
| `test-frontend` | `vitest run` + JUnit XML artifact | after lint-frontend |
| `burn-in-changed` | changed test files × 10 iterations | PRs only |
| `burn-in-full` | both full suites × 10 iterations | weekly cron (Sun 02:00 UTC) + manual dispatch |
| `report` | aggregated `$GITHUB_STEP_SUMMARY` | always |

Backend and frontend pipelines run in parallel. Test sharding is deliberately
skipped (backend ~35s, frontend ~2s); add `pytest-xdist` / `vitest --shard`
when a single suite exceeds ~5 minutes. No automatic retries — the suites are
deterministic unit tests, and burn-in (not retries) is the flakiness strategy.

## Secrets

**None required.** The backend `Settings()` needs `YTFLOW_LANGFUSE_*` values;
CI injects non-secret dummies pointing at `http://localhost:9` so the Langfuse
OTEL exporter fails fast and tests never touch a real backend.

If Slack notifications are wanted later: add a `SLACK_WEBHOOK_URL` repository
secret and an `if: failure()` step to the `report` job.

## Local parity

```bash
./scripts/ci-local.sh   # runs the same lint + test stages CI runs
```

## Merge gate (manual setup, repo admin)

Branch protection on `master` → require status checks:
`Lint (backend / ruff)`, `Lint (frontend / tsc)`,
`Test (backend / pytest)`, `Test (frontend / vitest)`,
`Burn-In (changed tests, 10x)`.

## Troubleshooting

- **Tests pass locally, fail in CI** — run `./scripts/ci-local.sh`; the most
  common cause is a dependency present locally but missing from
  `pyproject.toml` / `frontend/package.json` (CI installs from lockfiles only).
- **Langfuse connection noise in logs** — expected; the exporter points at a
  dead port by design and never blocks the run.
- **Burn-in failure** — the failing iteration number is in the job log; the
  test is flaky, not the pipeline. Fix the test before merging.
- **Cache misses** — uv cache keys off `uv.lock`, npm off
  `frontend/package-lock.json`; a lockfile change invalidates once, then re-caches.
