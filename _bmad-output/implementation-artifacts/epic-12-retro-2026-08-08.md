## What Went Well

### 1. Quality intent became executable policy

Story 12.1 converted hooks, open loops, pattern interrupts, event substance, source facts, and word budgets into a deterministic retention contract. The validator sits outside the generic semantic-retry boundary, so a structural violation cannot buy an unbounded or misleading model retry. Scoped repairs now receive the exact positional structure entries they must preserve.

### 2. Provider ownership is explicit and testable

Story 12.2 established one routing table for scenario stages. DeepSeek owns research, structure, cast, visual planning, and TTS normalization; Gemini owns writing, scene repair, runtime review/critic, and Epic 4 judging. Offline fakes are provider-scoped, so a misroute fails tests instead of being hidden by a provider-agnostic cassette.

### 3. Silent second-pass degradation now reaches the operator

Story 12.3 reads the final review and critic result before normalization discards their context. An unresolved second pass remains non-fatal but produces checkpoint-owned `scenario_quality`, reaches the scenario interrupt, survives SSE and artifact reload, and appears above gate controls. Deterministic repetition/slop metrics cannot be overwritten by the model.

### 4. Diversity was subordinated to fidelity

Story 12.4 added four closed narrative archetypes and selected one from a source-evidence inventory. The implementation rejects an interview, recovery, chronology, or incident framing when the corresponding evidence is absent. This prevents “diversity” from becoming a mechanism for fabricated SCP facts.

### 5. The decision story stopped safely when policy invalidated the premise

Story 12.5 did not build a Naver client after official policy made stored, edited, reused API audio ineligible for this pipeline. It narrowed the useful decision to Qwen stock versus clone, produced a blind package, recorded Jay's `qwen-clone` preference, and left production unchanged because listening preference was not treated as authorization to alter operator configuration.

### 6. Adversarial review consistently found boundary defects

Every story's review found issues that ordinary happy-path checks had missed: unwritable loop closures, incompatible Gemini response shapes, optional evidence that could fail a run, rejected-archetype rationale leaking into the next stage, and provider identity leaking through a supposedly blind filesystem layout. These reviews materially improved the delivered contracts.

## Challenges and Growth Areas

### 1. Live evidence lagged behind implementation breadth

The full production scenario chain has not yet jointly exercised Gemini writing, runtime review/critic, grounded contradiction output, and DeepSeek archetype inventory reporting with current production prompts. Offline routing is strong, but it cannot prove provider behavior or source-evidence honesty.

### 2. Review findings clustered at seams, not core algorithms

The recurring failures were transport shapes, cross-scene context, fallback handoff, checkpoint/UI delivery, metadata leakage, and error normalization. Local functions were usually correct; composition boundaries carried the risk.

### 3. Evidence bookkeeping drifted

Stories 12.3, 12.4, and 12.5 recorded stale or contradictory test counts. Story 12.2 later disproved the “pre-existing failures” classification inherited by Story 12.1. Story task states and change-log ordering also drifted during re-entry and review. The system needs command-captured verification summaries rather than manually copied counts.

### 4. A diagnostic field initially became a fatal surface

Grounded contradiction evidence was valuable, but the first implementation could fail an otherwise usable run when Gemini emitted an unevidenced optional claim. Review corrected the design to preserve one strict correction opportunity, then drop only the invalid claim with a visible warning.

### 5. Blind evaluation needs a multi-channel threat model

Story 12.5 first closed stdout leakage and later discovered that provider-named raw audio still revealed the mapping through the filesystem. A blind protocol must treat terminal output, directory layout, filenames, manifests, metadata, duration signatures, and generated artifacts as one disclosure surface.

### 6. The preferred voice is not the operating default

Jay preferred Qwen clone, but code and operator configuration still select Qwen stock. That is correct under the story's authorization boundary. The clone also read the representative scene materially faster, so a full-episode pacing check is required before an explicit configuration change.

## Story-by-Story Learnings

### Story 12.1

- Deterministic validation is most valuable when it is placed outside the model's correction budget.
- Per-scene generation requires explicit cross-scene context for obligations such as loop closure.
- Prompt examples can contradict hard validators; examples and schema must be reviewed as one contract.
- The inherited “three pre-existing failures” conclusion was later disproved by Story 12.2 and must not be reused as baseline evidence.

### Story 12.2

- Provider routing belongs in orchestration, with trace metadata derived from the same ownership table.
- A live probe of one provider path does not validate a second path that happens to use the same provider.
- OpenAI compatibility is a transport shape, not proof that every vendor honors the same response-format behavior.
- Gemini writes and judges the same prose; self-preference bias moved providers but was not eliminated.

### Story 12.3

- Non-fatal degradation must be persisted and delivered at the human decision point, not merely logged.
- Optional model diagnostics should never become a new fatal dependency for an otherwise valid pipeline result.
- Rule metrics must respect scene boundaries or they can manufacture evidence that does not exist in the script.

### Story 12.4

- Closed archetype selection is only as trustworthy as the source inventory it receives.
- Fallback must replace both the invalid choice and its rationale; otherwise rejected intent can leak downstream as prose.
- Categorical observability must stay outside numeric aggregation and winner arithmetic.

### Story 12.5

- Policy eligibility is an implementation gate, not a documentation afterthought.
- A listening preference and an authorization to alter production are separate decisions.
- Human evidence should remain incomplete rather than be filled with inferred scores.
- Blindness is a property of the complete evidence package, not only neutral filenames.

## Recurring Patterns

1. **Boundary-first risk:** all five stories found consequential issues at boundaries between stages, providers, state, files, or human review.
2. **Deterministic shell around probabilistic work:** closed vocabularies, pure validators, bounded retries, typed checkpoint payloads, and code-derived metrics consistently reduced ambiguity.
3. **One strict correction, then explicit degradation:** syntax/shape errors get one bounded correction; optional diagnostics degrade visibly instead of killing the run.
4. **Source fidelity outranks diversity:** archetype choice and fact propagation favor verified source structure over stylistic variation.
5. **Evidence must be measured at the authority boundary:** mocks prove wiring; live calls prove vendor behavior; gate/artifact/UI checks prove operator visibility.
