# Epic 14 Context: 시각 자산 층 — 큐레이션된 세트로 전환 (배경·D급·오브젝트)

## Goal

A full-length viewing verdict left five coupled visual defects — broken perspective, inconsistent backgrounds, people drawn into supposedly people-free backgrounds, narration that does not match the background or the character's pose, and art-style drift. The epic's single prescription is to stop generating a background per shot and instead **pick from human-approved asset sets** (locations, D-class and object cards). Consistency and background population are then filtered once, at approval time, instead of being guessed at every render; perspective/affordance and narration match become metadata queries against tagged candidates rather than hopes about a prompt. This is not a new capability but the unfinished reconciliation of an earlier plate-reuse attempt that was switched off because it keyed reuse to the scene and threw away each shot's prompt. Reuse is the intent; per-shot, prompt-aware reuse is the target.

## Requirements & Constraints

- **Reuse is the goal, not a regression.** When candidates run short, grow the set — never derive variants from one plate, and never "fix" reduced background diversity.
- **A human blind verdict is this epic's ground truth, and it reclassified the problem.** A blind pass over the shipped 43-tile sheet flagged 17 shots spanning five distinct classes (palette/style, compositing, unreadable background, scale, person-in-background) — most of what was filed as "style drift" is not style drift.
- **Machine visual labels have lost to human judgement three times here**, underestimating defect base rates by 2.4x and 3.5x. Any promotion decision needs a human looking at frames; a Claude-only label is a hypothesis.
- **Negative prompts are not the answer** to background population or style. Person tokens were already present when a framed portrait still rendered, and per-defect clause stuffing has wrecked renders twice.
- **Viewpoint/framing is not a function of prompt text.** Same prompt with a new seed flipped viewpoint category in 2 of 5 controlled pairs, and new high/low-angle prompt variants hit their target category in 2 of 20 renders. The only mechanism that has worked for this class is **detect-then-regenerate** (render, measure pixels, bump the seed).
- **Text pose instructions are ignored by the renderer.** Pose comes from approved card assets or pose conditioning, never from wording.
- **Never promote a prompt-derived checklist to a visual gate.** Those questions are leading — unreadable frames score higher because nothing in them contradicts. Sub-axes are worse than the aggregate. Visual adjudication must be blind.
- **Screen every prompt change as text before spending GPU**, and pin the request envelope, not just the prompt text.
- **A decision only ships if it reaches the code default** (dated verdict in the `config.py` comment; env files unpinned). The drift report is an instrument, not a build gate.
- **Undecidable vision judgements are accepted, not retried** — they consume no ladder rung but must raise a per-shot warning and must survive resume. Never count an unscreened frame as clean.
- **Identity floor holds.** No scene-conditioned human-insertion model is adopted; needed poses come from *more approved cards*. Style work must not loosen identity to close the style gap.
- **Writing to a character's angle paths is publishing.** Regeneration happens behind the approval gate, and an epoch promotes atomically — every key and pose together, always closing with the epoch bump.

## Technical Decisions

- **The shot is the image-generation unit**, mapped N:M onto narration sentences. Plate assignment, affordance judging and match scoring are per-shot; scene-level keying reproduces the known diversity collapse.
- **Plate selection is a pure filter chain** — framing, **location-key equality**, metadata, person, affordance — falling back to generation when nothing fits. **There is no viewpoint step: Story 14.8 removed it** (see the next bullet), so the axis is string equality on a closed enum and the selector never reads a plate's measured `viewpoint`. Plate metadata is measured once, so per-run cost is zero. The selector reads only camera angle, cast and location key; it discards the shot prompt, and semantic prompt match is explicitly out of scope (a location key is a room, not a scene).
- **The viewpoint matching axis is retired as unmeasurable, and 14.8 REPLACED it (shipped 2026-08-30).** Blind re-reads disagreed by 0.07–0.13 against a ±0.05 band, two independent judges flipped category on 2 of 5 identical images, and category width (0.20) is only twice the error. 14.8's Phase 1 research gate admitted exactly one of four candidate axes on the single criterion "reproduction error < tolerance": **`location_key` alone**, whose error is 0 because it DELETES the measurement rather than fixing one. The disclosed price is C4′: on run 4b35c0ed, 7 of 24 assigned plates sit at a viewpoint the shot's `camera_angle` did not ask for (5 of those shots carry cast, and `camera_angle` still picks the card's angle) — a viewing question with no threshold, not a coverage number. Existing plate viewpoint values are single-judge, single-reading and are KEPT on the assets: re-measure alongside, never overwrite, and never re-promote them to a selection predicate without a reproducible reading.
- **Affordance = asset metadata plus a runtime path for free-generated shots, under one shared judgement schema.** The runtime half is permanent; approved sets change its scope, not its existence.
- **A shared judgement prompt is not enough — pin the request envelope.** Image-before-text vs text-before-image is a deterministic order effect (5/7 vs 3/7, zero within-condition flips). Use image-first plus temperature 0 wherever an offline curator and the runtime must agree.
- **One VLM blind spot is permanent**: corpse/medical/gore plates draw a hard content rejection. Since those are routine output here, treating "undecidable" as "no standing room" would delete cast from that entire class.
- **Camera-angle field and prompt body do not conflict** (43/43 agreement); the contrary claim is false wherever it is still written. The field never reaches the background renderer's prompt but does drive cast-card angle selection, so it is not render-inert.
- **Do not build a floor/ceiling text-mass gate and do not widen the cast-suppression keyword vocabulary** — measured surface-noun mass runs opposite to the hypothesis, and high-angle plates are overwhelmingly usable.
- **Card sprites have a declared contract** (alpha profile plus sprite-validity reasons) enforced at the approval gate alongside the alpha check. A failing card is not a bad frame — casting it raises and kills the run.
- **Sampler-internal interventions are unavailable** (no installed custom node implements them); narration-match work goes through the prompt-rewriting layer, which is non-GPU and text-screenable.
- **Denominators must exclude rows whose correct answer is "no event"**, and any regeneration comparison needs a same-prompt control leg (re-rolling the old prompt alone moved the target axis by +7pp).
- **Close a class by sweeping the population, not by enumerating cases**, and honor a preregistered band when stamping data. Never lower a criterion after seeing the result — re-preregister instead, and confirm on a fresh sample.
- **The box has a working GPU**: AMD RDNA3 (gfx1100, 24 GB) under ROCm, with torch CUDA available. Earlier "no GPU" claims came from probing it with an NVIDIA-only tool while ComfyUI happened to be down — verify with a real render probe before declaring GPU-zero.

## Cross-Story Dependencies

- The research gate (14.0) blocked 14.2, 14.3 and 14.5; it is closed, each inheriting a constraint (assets-not-models for pose, metadata-plus-runtime for affordance, prompt rewriting for narration match, blind adjudication throughout).
- **14.8 shipped the axis; the flag did NOT ship.** `stock_plate_substitution_enabled` is still `False` with no `DECISIONS` row. Its unlock is an AND of exactly two conditions and **BOTH are open**: (a) coverage against a bar that can actually fail — 14.8's replacement criteria C1′/C2′/C3′ were all measured VACUOUS by a population sweep over the approved 42 (every one of the 14 keys holds 3 plates, `depicts_person=true` is 0/42, the one `has_person=true` plate is in an undemanded key, and the affordance knob ships OFF), so they carry zero evidence and closing (a) needs a different corpus; and (b) a human end-to-end viewing verdict on a run with substitution enabled. That run does not need the default flipped — `YTFLOW_STOCK_PLATE_SUBSTITUTION_ENABLED=true` turns it on for one run. **The five drafted augmentation plates are NOT required**: they were rendered to close a shortfall of the retired viewpoint axis, and the `location_key` axis does not demand them, so labelling/measuring/approving them is a separate decision with no story asking for it.
- **Enabling substitution is switching to the approval gate, not gaining a guard**: the plate path `continue`s past the runtime people-free guard, so a plate's only defence is its curation-time person verdict — and BOTH curators must have answered, since 14.8 made "nobody looked" mean `no_metadata` rather than "people-free".
- **Relight coupling is NOT an unlock condition.** It was carried as a third condition across several documents and has been falsified: the pair-building path is reachable only above the shipped harmonization tier, and the higher tier was rejected by a human viewing verdict. The defect is real, pinned by a test, and handed forward — it blocks nothing here.
- **Plate substitution and the affordance knob both ship OFF and interact** — the standing-room filter sits behind the substitution flag, so enabling them together is an explicit decision. The plate path also has **no runtime person guard**, mitigated only by approval labels.
- **Enabling substitution shrinks the reach of prompt-layer work** from every shot to the free-generated remainder — on run 4b35c0ed, from 43/43 to **19/43** (43 minus the 24 shots that take a plate: 12 shots carry no `location_key` at all, plus 7 close-up/POV). Later prompt measurements must state that denominator. **12/43 is the no-key count, not the reach**, and several documents printed it as the reach. Close-up and POV shots are permanent generation fallbacks by design, not defects.
- **14.3's flagged classes were routed, not fixed**: compositing and scale to the next end-to-end iteration, unreadable backgrounds to a newly registered deferred class, person-in-background to 14.1's approval gate. What 14.3 shipped is the attribution path that makes those pairs attributable in the next full run. A follow-up story (tracked outside the epics file) has since made the diagnosed depth-phrase edit as a 3-arm paired render and awaits a viewing verdict.
- **14.1 owns the "person inside a picture" class** (framed art, monitors, posters, models, statues) as an approval-gate criterion; the runtime guard deliberately does not fire on it, so until the sets cover free-generated shots this stays an accepted, documented risk.
- **14.5's pose half moved to 14.6**, which closed the non-retroactive card-library state behind gates and audit but produced no pixels: the regeneration batch, bulk standing-card regeneration, and the object set are all open. The object set has no consumer — shot data has no object axis and assets have no kind field — so its seams were handed forward. A staged epoch residue must be resolved first, because promotion is atomic.
- Pixel adjudication for the remaining axes rides the next full end-to-end iteration's blind judgement; no single story owns it.
