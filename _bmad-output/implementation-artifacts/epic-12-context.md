# Epic 12 Context: 대본·나레이션 품질 — 리텐션 구조 + 모델 분리 + 접지 게이트

## Goal

시각 품질 에픽들이 다루지 않은 **대본·나레이션** 절반을 닫는다. 시나리오 체인의 다단계 + scoped-repair 구조 자체는 충분하다는 판정이므로 재설계가 아니라 네 갈래 보강이다: ① 리텐션 설계를 프롬프트 속 형용사에서 검증 가능한 아웃라인 스키마로 끌어내고, ② writer=judge에서 오는 self-preference bias와 한국어 표면 품질 한계를 모델 분리로 완화하고, ③ 계산만 하고 버려지던 pass-2 판정을 사람에게 보이게 하고, ④ 원문 해부 구조가 지지하는 범위 안에서 이야기 아키타입을 넓힌다. 후속 스토리(12.6~12.8)는 라이브 산출물이 드러낸 짧은 대본·낭독조·기법 과잉·아웃라인 유래 날조를 같은 원칙으로 잇는다. **에픽 전체가 GPU를 요구하지 않아** GPU 필수 에픽과 완전 병렬이다.

## Stories

- Story 12.1: 리텐션 스키마 — 훅/오픈루프/페이싱을 검증 가능한 필드로
- Story 12.2: 모델 분리 — DeepSeek 기획 / Gemini 한국어 문장 + judge
- Story 12.3: pass-2 판정 활용 + 접지(grounded) 모순 검사
- Story 12.4: 스토리 아키타입 다변화 (구 Story 10.1)
- Story 12.5: TTS 프로바이더 비교 — Naver Clova Voice 검토 (조건부)
- Story 12.6: 원문에 살을 붙이는 각색
- Story 12.7: 문체 하네스 — 전체용 할당량을 씬별 배정으로
- Story 12.8: 아웃라인 접지 — 주인 없는 날조와 잘못 붙는 청구서

## Requirements & Constraints

- **리텐션은 검증 가능한 제약이다.** 훅 유형, 씬별 오픈루프 원장(심음/닫음), 패턴 인터럽트 간격, 비트별 단어 예산은 아웃라인 스키마의 필드여야 한다. 아웃라인 항목은 형용사가 아닌 사건 기반(누가/무엇을/결과). 심은 루프가 끝까지 안 닫히면 그 자체가 결함.
- **규칙으로 판정 가능한 것은 코드가 판정한다** — 길이·반복·slop·원장 청산·인용 존재 여부는 LLM 재호출 없는 결정론 체크로.
- **judge는 writer와 다른 계열이어야 한다는 것이 원칙**이나 현재 구성은 그렇지 않다(아래 트레이드오프). judge의 프로바이더·모델 정체성은 후속 편향 검토가 가능하도록 기록된다.
- **조용한 통과 금지.** 재시도 후에도 부정 판정인 시나리오가 아무 신호 없이 휴먼 게이트를 넘어가면 안 된다. 단 런을 실패시키지 않고 재재시도도 하지 않는다 — 판단은 사람 몫이고 bounded-retry 계약은 유지된다(세 번째 패스 추가 금지).
- **각색은 허용 범주의 선언이지 자유 창작 허용이 아니다.** 원문 사실의 감각적 묘사·장면화·빈칸을 질문으로 열기는 허용, 원문에 없는 새 사실 단언은 계속 금지. 이 범주들을 한 덩어리로 뭉개면 모델의 안전지대가 "원문 요약 낭독"이 된다.
- **아키타입은 원문 해부 구조의 함수다.** 로테이션이나 LLM 자유 선택으로 배정하면, 해당 addendum이 없는 SCP에서 인터뷰·실험 로그를 날조하고 그 손실은 `article_fidelity`로 직행한다. 다양성보다 사실성 우선 — 인벤토리가 하나만 지지하면 그대로 유지한다.
- TTS 프로바이더 교체는 확정 요구사항이 아니다 — 산출물은 교체가 아니라 청취 A/B 후 결정이며, 채택될 때만 코드가 바뀐다.

## Technical Decisions

- **2계열 모델 분리(Jay 결정)**: 기획/구조/파싱/TTS 정규화는 DeepSeek 유지(비용·스키마 순응도·프롬프트 캐시 자산 보존), 최종 한국어 문장 패스·씬 수리·런타임 review/critic·A/B eval judge는 Gemini. 신규 의존성 1개.
- **의도적으로 수용한 트레이드오프(기록 필수)**: Gemini가 자기 문장을 채점하므로 self-preference bias는 DeepSeek에서 Gemini로 **이동할 뿐 제거되지 않는다**. 완전 독립이 필요해지면 0-비용 대안이 남아 있다 — 문장만 Gemini로 넘기고 review/critic + eval judge는 DeepSeek에 유지하면 writer≠judge가 되고 신규 API 수는 그대로다. 승격 게이트 신뢰도는 judge 독립성에 직접 의존하므로 의심스러운 실측이 나오면 이 옵션으로 전환한다.
- 프로바이더 오류는 명시적이며 **프로바이더 간 조용한 폴백이 없다.** 모델 식별자는 코드가 아닌 config에 핀으로 고정(`YTFLOW_` 접두 pydantic settings) — 모델 교체는 config 변경이지 코드 변경이 아니다.
- **비치명적 품질 저하가 깨끗한 결과로 위장해선 안 된다** — 체크포인트가 소유한 경고 컨텍스트를 기존 게이트/SSE/아티팩트 경로로 전달한다. 미해결 pass-2 리뷰가 이 규약의 첫 구현체다.
- **판정은 아웃라인 유래와 나레이션 유래를 구분해 실어야 한다.** 구조 단계는 런당 1회이고 full-rewrite는 같은 아웃라인을 재사용하므로, 아웃라인發 날조는 재시도 루프가 구조적으로 도달할 수 없다 — 구분하지 않으면 청구서가 고칠 수 없는 층에 붙는다.
- **접지 검증은 축자 인용 + 부분문자열 대조로.** 사실 참조가 원문 인용을 함께 싣게 하면 헤지 손실("~로 보인다"의 소실)까지 코드로 확인 가능해진다. 양쪽 인용을 요구하는 기존 모순 보고 형식이 선례.
- **전체 기준 할당량을 씬별 실행에 걸지 말 것.** 작성 단계는 씬당 LLM 1회이고 각 호출은 자기 씬과 앞뒤 요약만 본다 — "대본 전체에서 3회"는 8배로 실행된다. 아웃라인이 특정 씬에 기법을 **배정**하는 형태가 이미 파이프라인 안에 있는 해법이며, 같은 요구가 두 군데 적혀 있으면 한쪽만 고쳐도 산출물이 안 변한다.
- 신규 서비스·추상 계층 분리 없음 — 결정론 체크는 시나리오 체인 내부의 순수 함수. 런타임 프롬프트는 저장소 파일이 진실의 원천이고 Prompt Hub로 시드된다(현재 DEV MODE: `production` 직승격, 승격 게이트 없음).

## UX & Interaction Patterns

모든 스테이지가 승인 게이트를 거치며(설정 불가, 고정 토폴로지), 시나리오 스테이지는 아티팩트 패널에서 텍스트를 읽고 인라인 편집한 뒤 별도로 승인하는 흐름을 이미 갖고 있다. 품질 판정 표면화는 이 경로에 얹는 것이지 새 UI 표면을 만드는 일이 아니다 — 사람이 결함을 **알고** 승인/거부하게 만드는 것이 목적이다.

## Cross-Story Dependencies

- **권고 착수 순서 12.2 → 12.1 → 12.3 → 12.4** (문장 품질이 먼저 올라가야 구조 개선이 체감된다 — 어색한 문장에 좋은 구조를 씌우면 어색함이 먼저 들린다). 12.5는 조건부.
- 12.4는 리서치 단계 출력에 **원문 addendum 인벤토리** 필드가 추가돼야 성립하고, 검증은 12.1이 확립한 결정론 체크 패턴을 그대로 쓴다.
- 12.3은 런타임 경로, 프롬프트 승격 median 게이트는 별개 경로 — 병존한다.
- 12.6 → 12.7 → 12.8은 라이브 판정에서 순차 파생된 사슬. 12.7 실측에서 관측된 접지 위반은 12.7의 회귀가 아니라 **12.8 소관**이다(오독 주의).
- 12.8은 12.1이 "review/critic이 소유한다"며 미뤄둔 아웃라인 접지 검사를 인수한다 — 인수받은 쪽이 아웃라인을 받지 못해 주인이 없어진 상태를 닫는 것.
- 12.2는 A/B 평가 서비스의 judge 호출까지 옮기므로 A/B 채점 경로에 닿는다. 12.5는 기존 TTS 정규화 규칙이 현행 엔진의 읽기 습성에 튜닝돼 있어, 엔진 교체 시 정규화 프롬프트 재검토가 딸려온다.
